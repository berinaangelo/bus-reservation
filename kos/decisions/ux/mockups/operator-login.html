Terminal Signal — UX decision

Operator Login

The entry point for OperatorStaff — admin accounts scoped to one operator, who manage their own Route/Trip/BusUnit/FareRule and view the trip manifest at boarding. Separate account system from the rider side, which has no login at all (guest checkout, reference_code + contact number for lookup). Email + password only — no forgot-password flow, MFA, or operator picker is decided for v1, so none of the three options below invent one. Option B — Split Panel is chosen, extended below with its default and submitting states.

Options considered

Option A — Centered Card

Plain centered card on a flat background — the single most recognized login shape on the web. Jakob's Law — an operator opening this once a day shouldn't have to parse anything novel to get to their trip manifest; the fastest login is the one that looks like every other login.

Option B — Split Panel

Brand/context panel on one side, form on the other — the same split-panel idiom already used for Seat Selection and Booking Lookup. Jakob's Law, applied within-product rather than web-wide: an operator who's seen the rider side of Terminal Signal recognizes the shape immediately, and the brand panel gives a place to state plainly that this console only manages one operator's own fleet.

Option C — Console / Terminal Style

Denser, mono-forward framing — mono field labels, a titled console frame, an operator-tier icon per the iconography system's admin overflow. Gestalt — similarity: deliberately reads as a different register from the rider-facing screens, so an operator always knows at a glance which side of the product they're on, without a persistent "you are staff" banner doing that work instead.
