Terminal Signal — UX decision

Operator Dashboard

The main console OperatorStaff land in after login — CRUD for their own Route, Trip, BusUnit and FareRule, scoped to one operator only (no operator picker, same decision as login — this console never shows another operator's fleet). All three options below use Routes as the worked example table, since the other three resources (Trips, Bus Units, Fare Rules) follow the same list/ add/edit/delete shape — only the navigation shell differs between options. Icons follow the operator-side tier — Tabler, not Lucide, per iconography.md's rule for fleet/route-editing screens. Option A — Sidebar + Table is chosen; B and C stay in the file for reference. CRUD forms (Add/Edit) and states (empty list, delete confirm) for Option A aren't built yet.

Options considered

Option A — Sidebar + Table

Persistent left nav across all four resources plus Manifest, full-width table on the right. Jakob's Law — this is the shape of nearly every admin panel (Rails admin, Django admin, Stripe dashboard) an operator has plausibly used before; the whole resource list is always one click away and current location never ambiguous.

Option B — Tabbed Workspace

Flat top tab bar across the four resources, no persistent sidebar column. Hick's Law — with exactly four resources (plus Manifest) there's no real hierarchy to justify a sidebar's extra chrome; a single row of five choices is scanned faster than a vertical list, and the table gets the full page width back.

Option C — Overview Launcher

Landing view leads with four at-a-glance stat cards (route count, trips today, fleet size, active fare rules) before any table — clicking a card drills into that resource's list, shown below already expanded for Routes. Peak-End Rule — the first thing an operator sees each day is "what's actually running today," not a bare CRUD table; the operational picture is the opening beat, CRUD is one click deeper.

States — Sidebar + Table

Add/Edit Route uses a slide-over drawer — panel enters from the right, table dims behind it rather than a centered modal or an inline row-expansion (the two other options considered). First overlay surface in the project: backdrop dimming is new, but the drawer panel itself keeps the flat language — a border-l separating it from the table, no shadow-*. Scoped to Routes only for this pass; Trip/Bus Unit/Fare Rule forms reuse this same drawer shape once it's confirmed.
